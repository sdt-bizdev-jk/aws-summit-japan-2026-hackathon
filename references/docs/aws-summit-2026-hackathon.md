# AWS Summit Japan 2026 AI-DLC ハッカソン

> 「AI 時代の新しい開発方法を学びながら『人をダメにする』サービスを考えよう!」

---

## 開催概要

本ハッカソンは、AWS が提唱する AI 時代の新しい開発手法 **AI-DLC（AI-Driven Development Lifecycle）** を実践するハッカソンです。AWS が開催する AI-DLC 勉強会で方法論を学びながら、テーマに沿ったソフトウェアを開発します。各フェーズの成果物をもとに審査が行われ、決勝に進んだチームは AWS Summit Japan 2026 で発表します。

> AI-DLC（AI 駆動開発ライフサイクル）は、**AI が実行し人間が監督する**という役割分担で、ソフトウェア開発全体を再構築する AI 時代の新しい開発手法。

### ハッカソンのテーマ

**「人をダメにするサービス」**

生成 AI の登場でソフトウェアでできることの可能性は飛躍的に広がった。Perl を開発した Larry Wall はプログラマーの三大美徳の1つとして「怠慢」を挙げている。今こそ、我々はどこまで人をダメにできるかを考える時。AI-DLC の Inception フェーズは AI によってチームのコミュニケーションを活発化し、より良いアイデアを生むために活用できる。知恵と AI を活用して、極限まで「人をダメにする」サービスを作り出そう。

**重要**: サービス自体が AI を使う必要はない。**人をダメにできるアイデア自体**を評価する。

## 審査について

### 選考の流れ

書類審査 → 予選 → 決勝 の **3 ステップ**で進行する。

#### 1. 書類審査（15 チーム選出予定）

- **結果発表**: 5月15日までに通知予定
- **提出物**:
  - 公開 GitHub リポジトリ URL
  - **Inception フェーズの成果物**（README、設計ドキュメント等）
- **審査基準**:
  - ビジネス意図（Intent）の明確さ
  - Unit 分解の適切さ
  - 創造性とテーマ適合性
  - ドキュメントの品質

#### 2. 予選会（5 チーム選出予定）

- **日時・場所**: 5月30日（土） ＠麻布台ヒルズ
- **提出物**:
  - 公開 GitHub リポジトリ（更新版）
  - 動作する **MVP デモ**とプレゼンテーション
- **審査基準**:
  - MVP デモの完成度
  - AI-DLC プロセスの実践と工夫
  - 創造性とテーマ適合性
  - プレゼンテーション

#### 3. 決勝

- **日時・場所**: 6月26日（金） AWS Summit Japan 2026 当日 ＠幕張メッセ
- **提出物**:
  - **AWS 上にデプロイされた**動作するデモ
  - 完成ソースコード（GitHub）
  - プレゼンテーション
- **審査基準**:
  - デモと完成度
  - AI-DLC プロセスの実践と工夫
  - 創造性と**ビジネス価値**
  - プレゼンテーション

## このドキュメントを AI-DLC コンテキストで使うときの要点

Inception フェーズの成果物として書類審査で評価される観点をハイライト:

1. **ビジネス意図（Intent）の明確さ** — なぜこのサービスか、誰の何を「ダメ」にするのか
2. **Unit 分解の適切さ** — AI-DLC の単位への分け方
3. **創造性とテーマ適合性** — 「人をダメにする」テーマとどう噛み合うか
4. **ドキュメントの品質** — README・設計ドキュメントの読みやすさ

成果物として最低限必要なもの:
- 公開 GitHub リポジトリ
- README
- 設計ドキュメント

予選以降で必要になるもの（書類審査時点では不要）:
- 動作する MVP デモ（予選）
- AWS デプロイ済み動作デモ + 完成ソースコード（決勝）
