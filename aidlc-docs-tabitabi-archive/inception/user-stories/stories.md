# ユーザーストーリー（v2）

## 概要
ユーザージャーニーベースで分解。体験フロー（旅に出る→道中→途中下車→一覧→横断分析）に沿ったエピック構成。

※ v1から体験フローの変更なし。アーキテクチャ変更（EKS + DocumentDB + React Native）はユーザー体験レベルのストーリーに影響しないため、ストーリー構造・受入条件はv1を引き継ぐ。

## 優先度ラベル
- **P1（最優先）**: 最小ループ完結に必須（旅に出る→途中下車→一覧）
- **P2（高）**: 横断分析 + 次の旅先提案
- **P3（中）**: 道中体験・通知
- **P4（低）**: ソーシャル機能

## Epic 1: 旅に出る（FR-01）

### Story 1.1: テンプレートから旅に出る
**As** はじめてのタビビト（ユキ）
**I want to** テンプレートから「何を始めるか」を選んで旅に出たい
**So that** 30秒以内に始められ、考える負担がない

**優先度**: P1
**ペルソナ**: ユキ、ケンタ、ミサキ

#### 受け入れ基準
```gherkin
Given アプリを開いている
When テンプレート一覧から「ランニング」を選択する
Then 旅が開始され、道標が表示される

Given アプリを開いている
When テンプレートを選択して旅に出る操作を完了する
Then 操作開始から完了まで30秒以内である
```

---

### Story 1.2: 自由入力で旅に出る
**As** リピーター（ケンタ）
**I want to** 自由入力で自分だけの旅を始めたい
**So that** テンプレートにない活動も旅にできる

**優先度**: P1
**ペルソナ**: ケンタ、ミサキ

#### 受け入れ基準
```gherkin
Given アプリを開いている
When 自由入力欄に「毎朝ストレッチ」と入力して旅に出る
Then 旅が開始され、入力内容に基づいた道標がAIにより生成される

Given 自由入力で旅に出た
When 道標が表示される
Then 道標は「ここまでやったらこの景色が見える」形式である
```

---

### Story 1.3: AI道標の生成
**As** はじめてのタビビト（ユキ）
**I want to** 旅に出たときに「ここまでやったらこの景色が見える」という道標を見たい
**So that** ゴールではなく途中の発見が提示され、プレッシャーを感じない

**優先度**: P1
**ペルソナ**: ユキ、ケンタ、ミサキ

#### 受け入れ基準
```gherkin
Given 旅に出る操作を完了した
When 道標が表示される
Then 2〜4個の道標が提示され、各道標は達成ではなく発見・体験の形式である

Given 道標が表示される
When 内容を確認する
Then 「〜できるようになる」ではなく「〜を発見する/〜に気づく」形式である
```

## Epic 2: 道中（FR-02）

### Story 2.1: 任意の進捗報告
**As** リピーター（ケンタ）
**I want to** 自分から進捗を報告できる（任意）
**So that** 気が向いたときだけ記録でき、義務感がない

**優先度**: P3
**ペルソナ**: ケンタ

#### 受け入れ基準
```gherkin
Given 旅の道中にいる
When 進捗報告ボタンを押して「今日走った」と入力する
Then 報告が記録され、道標の進捗に反映される

Given 旅の道中にいる
When 何も報告しない
Then アプリから催促や通知は来ない（道標通知を除く）
```

---

## Epic 3: 途中下車（FR-03）

### Story 3.1: 自分から途中下車する
**As** はじめてのタビビト（ユキ）
**I want to** 自分から「ここで降りる」と宣言して旅を終えたい
**So that** やめることが自然な行為として扱われる

**優先度**: P1
**ペルソナ**: ユキ、ケンタ、ミサキ

#### 受け入れ基準
```gherkin
Given 旅の道中にいる
When 「ここで降りる」ボタンを押す
Then 途中下車フローが開始され、AIが「道中で見た景色」を提示する

Given 途中下車フローが開始された
When AIが景色を提示する
Then 1〜3個の「得たもの」候補が表示される
```

---

### Story 3.2: フェードアウト後の途中下車確認
**As** はじめてのタビビト（ユキ）
**I want to** 3日間何もしなかったときにそっと確認してほしい
**So that** 自然にフェードアウトしても旅が宙ぶらりんにならない

**優先度**: P1
**ペルソナ**: ユキ、ミサキ

#### 受け入れ基準
```gherkin
Given 旅の道中で3日間活動がない
When フェードアウト確認通知が届く
Then 「降りますか？」と穏やかに確認され、圧をかけない文面である

Given フェードアウト確認通知が届いた
When 「降りる」を選択する
Then 通常の途中下車フローと同じくAIが景色を提示する
```

---

### Story 3.3: 道中で見た景色の編集
**As** リピーター（ケンタ）
**I want to** AIが提示した「得たもの」を編集・追加したい
**So that** 自分の言葉で景色を残せる

**優先度**: P1
**ペルソナ**: ケンタ、ユキ

#### 受け入れ基準
```gherkin
Given AIが「道中で見た景色」を提示した
When 候補をそのまま採用する
Then その内容で途中下車が確定し、一覧に追加される

Given AIが「道中で見た景色」を提示した
When 候補を編集して「自分のペースが分かった」に変更する
Then 編集後の内容で途中下車が確定する
```

## Epic 4: 一覧画面（FR-04）

### Story 4.1: 途中下車した旅の一覧表示
**As** リピーター（ケンタ）
**I want to** 途中下車した旅の一覧をメイン画面で見たい
**So that** 自分の旅の履歴が一目で分かる

**優先度**: P1
**ペルソナ**: ケンタ、ユキ、ミサキ

#### 受け入れ基準
```gherkin
Given 複数の旅を途中下車済み
When メイン画面を開く
Then 途中下車した旅が一覧で表示され、各旅に「道中で見た景色」が紐づいている

Given メイン画面を開いた
When 旅の数を確認する
Then 「旅の数: N」が表示され、始めた回数が肯定的に示される
```

---

### Story 4.2: 旅の詳細表示
**As** リピーター（ケンタ）
**I want to** 個別の旅の詳細（景色、期間）を見たい
**So that** 過去の旅を振り返れる

**優先度**: P1
**ペルソナ**: ケンタ、ユキ

#### 受け入れ基準
```gherkin
Given 一覧画面で旅を選択する
When 詳細画面が表示される
Then 旅の名前、道中で見た景色、旅に出た日、途中下車した日が表示される
```

## Epic 5: 横断分析 + 次の旅先提案（FR-05）

### Story 5.1: パターン発見
**As** リピーター（ケンタ）
**I want to** 複数の旅を横断して「自分が本当は何を求めていたか」のパターンを知りたい
**So that** バラバラの途中下車に意味を見出せる

**優先度**: P2
**ペルソナ**: ケンタ

#### 受け入れ基準
```gherkin
Given 3回以上の途中下車がある
When 横断分析を表示する
Then AIが旅のパターンを分析し、「あなたが求めていた方向性」を提示する

Given 横断分析が表示された
When 内容を確認する
Then 具体的な旅の名前を引用しつつ、共通する方向性が言語化されている
```

---

### Story 5.2: 次の旅先提案
**As** リピーター（ケンタ）
**I want to** パターンに基づいて「次に始めたら面白そうなこと」を提案してほしい
**So that** 次の一歩のヒントが得られる（行くかどうかは自分次第）

**優先度**: P2
**ペルソナ**: ケンタ

#### 受け入れ基準
```gherkin
Given 横断分析でパターンが表示されている
When 「次の旅先」提案を見る
Then パターンに基づいた1〜3個の提案が表示され、各提案に理由が添えられている

Given 次の旅先が提案された
When 提案内容を確認する
Then 「またやめていい」前提の文面であり、プレッシャーを感じない
```

---

## Epic 6: プッシュ通知（FR-07）

### Story 6.1: 道標ベースの通知
**As** はじめてのタビビト（ユキ）
**I want to** 道標に近づいたときに軽い通知を受け取りたい
**So that** 旅の存在を忘れずにいられる（ただし圧はない）

**優先度**: P3
**ペルソナ**: ユキ、ケンタ

#### 受け入れ基準
```gherkin
Given 旅の道中で道標に近づいた
When プッシュ通知が届く
Then 「あと1回で〜の道標です。やってもやらなくてもいいですけど。」形式の文面である

Given プッシュ通知が届いた
When 文面を確認する
Then 圧をかけない表現であり、行動を強制しない
```

---

### Story 6.2: フェードアウト確認通知
**As** はじめてのタビビト（ユキ）
**I want to** 3日間何もしなかったときにそっと通知が来てほしい
**So that** 旅を宙ぶらりんにせず、自然に途中下車できる

**優先度**: P3
**ペルソナ**: ユキ、ミサキ

#### 受け入れ基準
```gherkin
Given 旅の道中で3日間活動がない
When フェードアウト確認通知が届く
Then 「最近どうですか？降りるなら降りるで大丈夫ですよ」形式の穏やかな文面である
```

---

## Epic 7: ソーシャル機能（FR-06）

### Story 7.1: 匿名タイムライン閲覧
**As** ソーシャル観察者（ミサキ）
**I want to** 他のユーザーの途中下車が匿名で流れてくるタイムラインを見たい
**So that** 「自分だけじゃない」と安心できる

**優先度**: P4
**ペルソナ**: ミサキ、ユキ、ケンタ

#### 受け入れ基準
```gherkin
Given タイムライン画面を開く
When 他ユーザーの途中下車が表示される
Then 匿名で「〇〇を△日で途中下車」形式の情報が時系列で表示される

Given タイムラインを閲覧する
When 個人を特定できる情報を探す
Then ユーザー名やデバイス情報は一切表示されない
```

## INVEST基準チェック

| 基準 | 適合状況 |
|---|---|
| **Independent** | 各ストーリーは独立して実装可能（Epic間の依存は優先度で管理） |
| **Negotiable** | 受け入れ基準は最小限で、実装方法に余地がある |
| **Valuable** | 各ストーリーがユーザーに直接価値を提供する |
| **Estimable** | スコープが明確で見積もり可能 |
| **Small** | 1ストーリー = 1つの明確な機能単位 |
| **Testable** | Given/When/Then形式で検証可能 |
