# Integration Test Instructions — cycle-6 (stats-feature)

ユニット間 (stats-core ↔ dashboard-page ↔ ide-stats-bridge) の連携を実機 Chrome + Kiro で確認する手動 E2E。

## Setup
1. `chrome://extensions/` で `extension/` を読み込み (v0.6.0)、更新ボタンを押す
2. Claude.ai に登録娯楽サイトが 1 件以上あること (Options Page で確認)
3. (IDE 連携を試す場合) Kiro で VS Code 拡張をロード + Hook 設定済み (cycle-4 同様)

## Test Scenarios

### IT-61: stats-core → dashboard-page (Chrome 単独の記録→表示)
- **手順**:
  1. Claude.ai でプロンプト送信し、N秒以上の待ちを発生させる → 娯楽タブに自動切替
  2. AI 完了 → Claude.ai に自動で戻る
  3. 戻った後すぐに Claude.ai 画面をスクロール (集中復帰操作)
  4. ダッシュボード (`chrome-extension://<id>/dashboard/dashboard.html` or Options のバナー) を開く
- **期待**:
  - 「今日ダメになった時間」「待ち時間合計」「待ちサイクル回数(1回)」が表示
  - 余暇種別内訳に切替先ジャンル (例: 動画) のバー
  - 集中復帰までの平均に数秒の値、離脱継続率 100%
  - 週次トレンドの当日バーが立つ

### IT-62: 未復帰 (M-07) の記録
- **手順**: IT-61 の後、AI 完了で戻った後 **120 秒間何も操作しない**。その後ダッシュボードを開く
- **期待**: 「戻れなかった回数」が 1 増える。集中復帰平均には算入されない

### IT-63: 再離脱 (M-04) の記録
- **手順**: AI 完了で戻った直後 (30秒以内) に、自分で娯楽タブへ手動で切り替える (新しいプロンプトは送らない)
- **期待**: 離脱継続率が下がる (該当サイクルが「継続失敗」にカウント)

### IT-64: 正規離脱の除外 (BR-91)
- **手順**: AI 完了で戻った直後に、続けて新しいプロンプトを送信 (→ 新サイクルで娯楽タブへ自動切替)
- **期待**: この離脱は「継続失敗」に数えられない (離脱継続率が不当に下がらない)

### IT-65: 切替なしサイクル (F6) の記録
- **手順**: 娯楽サイトを 0 件にして (または探索失敗状況で) 待ちを発生させ、完了させる
- **期待**: 待ち時間・回数には算入、娯楽時間は 0。ダッシュボードでサイクル回数が増える

### IT-66: ide-stats-bridge (Kiro 待ち → Chrome ダッシュボード合算)
- **手順**: Kiro でプロンプト送信 (promptSubmit Hook) → ブラウザ起動、agentStop で Kiro 復帰。ダッシュボードを開く
- **期待**: IDE 由来サイクル (source=ide) が待ち時間・娯楽時間・余暇種別に合算される。集中復帰秒数には影響しない (C4=B)

### IT-67: 週次トレンドのトグル (F7=C)
- **手順**: ダッシュボードの週次トレンドで「ダメになった時間」/「待ち時間」を切替
- **期待**: バーの高さが指標に応じて再描画される

### IT-68: 空状態 (BR-101)
- **手順**: stats_events が空の状態 (新規プロファイル等) でダッシュボードを開く
- **期待**: 「まだ記録がありません」の空状態表示
