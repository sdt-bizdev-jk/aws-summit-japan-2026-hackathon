## 依存関係の詳細

### Unit 2 → Unit 1（強い依存）
- **理由**: analysis は trips コレクションのデータを読み取り、AIService（utils）を使用する
- **必要なもの**: Trip ドキュメント構造、AIService の analyze_trip_patterns / suggest_next_trips メソッド
- **制約**: Unit 1 の trips models + utils/ai_generator.py が完成していること

### Unit 3 → Unit 1（強い依存）
- **理由**: notifications は trips データを参照し、AIService で通知文面を生成する
- **必要なもの**: Trip ドキュメント構造、AIService の generate_notification_copy メソッド、DeviceAuthMiddleware
- **制約**: Unit 1 の trips models + utils が完成していること

### Unit 4 → Unit 1（参照依存）
- **理由**: social は trips コレクションの途中下車済みデータを読み取る
- **必要なもの**: Trip ドキュメント構造（status="dropped_off" のデータ）
- **制約**: Unit 1 の trips models が完成していること（AIService は不要）

### Unit 5 → Unit 1（強い依存）
- **理由**: モバイルアプリの最小ループ（旅の開始〜途中下車〜一覧）に trips API が必須
- **必要なもの**: `/api/trips/` 系エンドポイントが動作すること
- **制約**: Unit 1 のAPI が利用可能であること（ローカル or デプロイ済み）

### Unit 5 → Unit 2, 3, 4（参照依存）
- **理由**: 横断分析・通知・タイムライン画面の実装に各APIが必要
- **必要なもの**: 各ユニットのAPIエンドポイント
- **制約**: 段階的に統合可能（Unit 1 のAPIだけで開発開始できる）

### Unit 6 → Unit 5（設計参考）
- **理由**: Web版はモバイル版と同じ画面構成・フローを持つ
- **必要なもの**: Unit 5 の画面設計・コンポーネント構成を参考にする
- **制約**: 実装依存はなし（別コードベース）

### Unit 6 → Unit 1〜4（参照依存）
- **理由**: Web版も同じバックエンドAPIを呼び出す
- **必要なもの**: 全バックエンドAPIエンドポイント
- **制約**: 段階的に統合可能

### Unit 8 → Unit 7（強い依存）
- **理由**: セキュリティ/監視はEKS/VPC/ALBの上に構築される
- **必要なもの**: VPC、EKSクラスター、ALB が存在すること
- **制約**: Unit 7 の CDK Stack がデプロイ済みであること

## 開発順序制約

### 必須順序（破れない）
```
Unit 1 ──→ Unit 2
Unit 1 ──→ Unit 3
Unit 1 ──→ Unit 4
Unit 1 ──→ Unit 5 (最小ループ部分)
Unit 7 ──→ Unit 8
```

### 推奨順序（効率のため）
```
Unit 1 ──→ Unit 2 ──→ Unit 3 ──→ Unit 4  (バックエンド順次)
Unit 1 完了後 ──→ Unit 5 開始可能
Unit 5 完了後 ──→ Unit 6 開始可能（後回し）
Unit 7 は任意のタイミングで開始可能（デプロイ時に必要）
```

### 並行開発可能な組み合わせ
- Unit 2 + Unit 3 + Unit 4（Unit 1 完了後、互いに独立）
- Unit 5 + Unit 2〜4（Unit 1 完了後、フロントとバックを並行）
- Unit 7 + Unit 1〜5（インフラはアプリ開発と並行可能）

## クリティカルパス

最小限の動作確認（PoC デモ）に必要なユニット:

```
Unit 1 (trips-backend) → Unit 5 (mobile-app) → Unit 7 (infrastructure-base)
```

この3ユニットが完了すれば、旅の開始〜途中下車〜一覧表示の最小ループがモバイルで動作し、EKS上にデプロイ可能。

**フルスコープ**:
```
Unit 1 → Unit 2 → Unit 3 → Unit 4 → Unit 5 → Unit 6 → Unit 7 → Unit 8
```

## リスク・注意点

| リスク | 影響ユニット | 対策 |
|---|---|---|
| Bedrock API のレート制限 | Unit 1, 2, 3 | AIService にリトライ・バックオフ実装 |
| DocumentDB 接続設定 | Unit 1〜4 | Unit 1 で接続パターンを確立、他ユニットは踏襲 |
| FCM 設定の複雑さ | Unit 3, 5 | Unit 3 でサーバー側、Unit 5 でクライアント側を個別に検証 |
| EKS 構築の時間 | Unit 7 | ローカル開発環境（Docker Compose）を先に整備 |
| Snowflake 連携 | Unit 8 | PoC段階ではバッチ連携のみ、リアルタイムは将来 |
