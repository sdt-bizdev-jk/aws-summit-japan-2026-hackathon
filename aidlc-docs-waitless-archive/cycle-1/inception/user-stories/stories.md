## ストーリー一覧

### US-01: 待ち時間の発生を察知してくれる

**As** タカシ
**I want** Claude.ai でプロンプトを送信して数秒以上 出力が続いた時に、待ち発生を WaitLess が自動で察知する
**So that** 出力が短い時に余計な切替が起きず、長い時だけ娯楽タブへ移れる

**対応FR**: FR-01, FR-02, FR-03

**Acceptance Criteria**:
- **AC1**: Given Claude.ai タブで応答ストリーミング中である / When ストリーミングが しきい値 (デフォルト 5秒) 以上 連続して続いている / Then WaitLess は「待ち発生」イベントを発火する
- **AC2**: Given Claude.ai タブで応答ストリーミング中である / When ストリーミングがしきい値未満で完了する / Then WaitLess は「待ち発生」イベントを発火しない
- **AC3**: Given アクティブタブが Claude.ai 以外である / When 任意の DOM 変化が起きる / Then WaitLess は反応しない

---

### US-02: 待ち発生で登録した娯楽サイトに自動切替する

**As** タカシ
**I want** 待ち発生イベントが起きたら、登録した娯楽サイトの中から優先順位上位のものに自動で切替えてくれる
**So that** タブを手で探さなくても、すぐに気晴らしを始められる

**対応FR**: FR-04, FR-05, FR-06

**Acceptance Criteria**:
- **AC1**: Given 娯楽サイトが優先順位付きで 1件以上 登録されている AND 上位エントリと同 URL/同ドメインのタブが既に開いている / When 待ち発生イベントが発火する / Then その既存タブをアクティブ化する
- **AC2**: Given 娯楽サイトが登録されている AND どのエントリにも一致するタブが開かれていない / When 待ち発生イベントが発火する / Then 優先順位 1位 のエントリの動画URLで新規タブを開いてアクティブ化する
- **AC3**: Given 複数の娯楽サイトが登録され、複数のエントリに一致するタブが開いている / When 待ち発生イベントが発火する / Then 優先順位の最も高いエントリに対応するタブが選択される

---

### US-03: 切替先で動画が自動再生されて、すぐに楽しめる

**As** タカシ
**I want** 娯楽タブに切替わった時に、登録した動画が自動再生されている状態で迎えてくれる
**So that** 切替直後から能動的に何もしなくても気晴らしが始まる

**対応FR**: FR-04, FR-06

**Acceptance Criteria**:
- **AC1**: Given 切替先が新規に開かれた登録 URL である / When タブがアクティブ化される / Then 登録された動画URLがロードされ、ブラウザの自動再生が許可される範囲で動画が再生される
- **AC2**: Given 切替先が既存タブで、動画コンテンツが一時停止状態である / When そのタブがアクティブ化される / Then WaitLess は再生再開を試行する
- **AC3**: Given ブラウザの自動再生ポリシー等で再生が失敗する / When 再生試行が失敗する / Then タブ切替自体は成功し、ユーザー操作の妨げにならない

---

### US-04: 出力完了で Claude.ai タブに即座に戻る

**As** タカシ
**I want** Claude.ai の出力が完了したら、何もしなくても WaitLess が自動で Claude.ai タブに戻してくれる
**So that** 完了通知に気を回さずに娯楽を楽しめる、かつ完了後すぐに作業へ復帰できる

**対応FR**: FR-07, FR-08

**Acceptance Criteria**:
- **AC1**: Given 娯楽タブがアクティブで、Claude.ai タブはバックグラウンドで応答ストリーミング中である / When Claude.ai のストリーミング応答が完了したことを DOM 変化から検知する / Then 即座に Claude.ai タブをアクティブ化する
- **AC2**: Given Claude.ai タブが既にアクティブな状態で出力が完了した / When 完了を検知する / Then タブ切替は発生せず、現状を維持する
- **AC3**: Given 待ち発生イベント発火後の 1サイクル / When 完了検知後に Claude.ai タブへ戻った / Then 1サイクルが終了し、次の待ち発生まで WaitLess はアイドル状態に戻る

---

### US-05: 娯楽サイトとしきい値を設定する (オプションページ全部入り)

**As** タカシ
**I want** Chrome 拡張のオプションページから、娯楽サイトの登録/編集/削除/並び替え と、待ち発生のしきい値 (秒) を一画面で管理する
**So that** 1度の操作で自分好みの動作にカスタマイズし、その後は意識せずに WaitLess を使える

**対応FR**: FR-04, FR-09, FR-10, FR-11

**Acceptance Criteria**:
- **AC1**: Given オプションページを開いている / When 「ドメイン (または URL) + 自動再生用 URL」を入力して追加する / Then エントリがリストに追加され、`chrome.storage.local` に永続化される。既存エントリの編集・削除も同様に永続化される
- **AC2**: Given 登録済みの娯楽サイトが複数ある / When ドラッグ操作 や 矢印ボタン などで並び順を変更する / Then 新しい優先順位が永続化され、以後の自動切替に反映される
- **AC3**: Given オプションページの「待ち発生しきい値 (秒)」入力欄 / When 値 (例: 3秒) を入力して保存する / Then 値が永続化され、以後の待ち発生判定に反映される。デフォルト値は 5秒 とする

---

### US-06: 拡張機能をインストールして、すぐに使い始められる

**As** タカシ
**I want** 拡張機能をインストールしてオプションページを開いた時に、最低限の使い方が一目で分かり、初回登録までスムーズに辿り着ける
**So that** インストール直後の数分で WaitLess を実用状態にできる

**対応FR**: FR-09, FR-10 (初回設定導線)

**Acceptance Criteria**:
- **AC1**: Given 拡張機能をインストール直後で、`chrome.storage.local` に登録エントリが 0件 である / When オプションページを開く / Then 「最低 1件 を登録すると WaitLess が動作する」旨の説明が表示される
- **AC2**: Given 説明文が表示された画面 / When ユーザーが入力欄に最初のエントリを登録する / Then 登録は永続化され、以後の待ち発生で自動切替が動く状態になる
- **AC3**: Given しきい値を未調整 (デフォルト 5秒) / When ユーザーが操作せずに登録だけ済ませた / Then デフォルト 5秒 で動作し、タカシは追加調整なしに WaitLess を使える

## ノンゴール (本サイクルでは扱わない)

要件 §7 のアンチスコープと同期。ストーリーには含めず、ここに注記として残す:

1. **待ち時間/娯楽時間の統計・ログ**: 統計ダッシュボード、累計時間トラッキング 等は持たない
2. **Claude.ai 以外のAIサービス対応**: ChatGPT / Gemini / 他LLMチャットUIへの拡張は今回しない (将来の設計余地も今回は確保しない)
3. **ON/OFFトグル / 一時停止機能**: 常時ON。ユーザーが操作で止める仕組みは作らない
4. **ポップアップUIへの設定統合**: 拡張機能ツールバーアイコンのポップアップに設定UIは置かない (オプションページのみ)
5. **端末間同期**: `chrome.storage.sync` は使わない (端末内完結)
6. **OS通知 / バッジ / 効果音**: タブ自動切替を以て完了通知とする
7. **TypeScript / React / ビルドツール**: 素のJS/HTML/CSS、ビルド不要
8. **多言語化 (i18n)**: 日本語UIのみ

これらは設計・実装段階で検討対象外であり、レビュー時の指摘事項にもしない。
