## 1. プロジェクト概要

### 1.1 名称と由来
- **名称**: WaitLess
- **由来**: "Wait" + "Less" — 待ち時間 (の体感) を減らす、または「待ち」がない (less = 〜なし)
- **コンセプト一行**: 生成AI (Claude.ai) の出力待ち時間を、登録した娯楽タブへの自動切替で快適に消化し、出力完了したら自動でAIタブに戻ってくる Chrome 拡張機能

### 1.2 種別
- Chrome 拡張機能 (Manifest V3)
- デスクトップ Chrome ブラウザ専用

### 1.3 完成度ゴール
**MVP** — 主要機能が一通り使える状態で、Chrome Web Store 申請を見据えた品質。

### 1.4 本サイクルの開発スコープ
- INCEPTION フェーズ全体 (要件 → ユーザーストーリー → 計画 → 設計 → ユニット分割) を完了
- CONSTRUCTION フェーズで **1ユニット分のコード生成まで** 実施
- 1ユニットの選定基準は Units Generation 完了時に改めて協議 (CQ9=C)

## 3. 想定ユーザー

Claude.ai を業務または個人用途で日常的に使い、出力待ちの数十秒〜数分を「ぼーっと画面を見る」のではなく、動画視聴や SNS など別のアクティビティに有効活用したいユーザー。とりわけ:

- ストリーミングが終わるまでただ眺めてしまい、結果として効率が落ちる感覚を持っている人
- 複数のタブを行き来する操作が手間に感じている人
- 通知ではなく「画面が娯楽から作業に戻る」体験で完了を知りたい人

## 4. 中核体験フロー

```
+---------------------------------------------------------------+
|                       中核体験フロー                          |
+---------------------------------------------------------------+

  [1] ユーザーが Claude.ai でプロンプト送信
                         |
                         v
  [2] WaitLess が Claude.ai タブのストリーミング応答を DOM 監視
                         |
                         v
  [3] ストリーミングが N 秒以上 続いていることを検知
       (短い応答は無視 = 切替えない)
                         |
                         v
  [4] 登録された娯楽サイトの優先順位リストを参照
       +- 上位から順に「同URL/同ドメインのタブが既に開いているか」確認
       |   +- 開いている  -> 既存タブへ切替 + 必要なら再生再開
       |   +- どこにもない -> 登録された動画URLで新規タブを開いて切替
                         |
                         v
  [5] ユーザーは娯楽タブで動画視聴等を楽しむ
                         |
                         v
  [6] WaitLess は Claude.ai タブの DOM を監視し続け、出力完了を検知
                         |
                         v
  [7] Claude.ai タブへ即時自動切替 (= 完了通知)

+---------------------------------------------------------------+
```

### 4.1 解釈の明示 (整合性ノート)

優先順位リストの上位から順に「同URL (または同一ドメイン) のタブが既に開いているか」を確認する。開いていればそのタブへ切替えて動画再生を促す (停止していれば再生再開)。どこにも開いていなければ、登録された動画URLで新規タブを開いて切替える。

## 5. 機能要件 (FR)

### FR-01: Claude.ai タブの自動検出
拡張機能は、現在のアクティブタブまたはバックグラウンドタブが Claude.ai のドメイン (`claude.ai`) であるかを判定できなければならない。

### FR-02: Claude.ai 応答ストリーミング状態の DOM 監視
拡張機能は、Claude.ai のページ DOM を観察し、応答ストリーミング中であるかどうかを判定できなければならない (停止ボタンの存在/状態、ストリーミングインジケータ、メッセージ末尾のカーソル等の DOM シグナルから推定する)。

### FR-03: ストリーミング継続 N 秒判定
ストリーミングが **N秒以上 連続** したと判定できた瞬間に「待ち発生」イベントを発火する。短い応答 (N秒未満) では切替を発火しない。

### FR-04: 娯楽サイト登録 (ドメイン + 自動再生URL のペア)
ユーザーは娯楽サイトを **「ドメイン (または同等の識別子)」と「自動再生用URL」のペア** として登録できなければならない。複数のエントリを **優先順位** 付きで保持できる。例:

```
1位: youtube.com  / https://www.youtube.com/playlist?list=PLxxxx
2位: x.com        / https://x.com/home
3位: nicovideo.jp / https://www.nicovideo.jp/ranking
```

### FR-05: 既存娯楽タブの探索と優先順位選択
「待ち発生」イベント発生時、優先順位の上位から順に、登録された対象 (URL/ドメイン) と一致するタブが現存するかをブラウザ全体から探索する。最初にヒットしたタブを切替先とする。

### FR-06: 娯楽タブへの自動切替 (既存 or 新規)
- FR-05 でヒットした既存タブがあれば、そのタブを **アクティブ化** する。
- どこにもヒットしなければ、優先順位 1位 のエントリの **動画URL** で新規タブを開き、それをアクティブ化する。
- 切替後、可能な範囲で動画再生をトリガーする (停止中なら再生開始の試行)。

### FR-07: Claude.ai 応答完了の DOM 検知
拡張機能は、Claude.ai タブの DOM を監視し続け、ストリーミング応答が **完了した** ことを検知できなければならない (停止ボタンが消える/再送ボタンが出現する 等のシグナル)。

### FR-08: Claude.ai タブへの自動戻り (即時)
完了検知の瞬間に、即座に Claude.ai タブをアクティブ化する。ユーザーが現在何のタブにいても強制的に切替える (= 完了通知の代用)。

### FR-09: オプションページでの設定UI
Chrome 拡張のオプションページ (`chrome://extensions` から開くタイプ、または `chrome.runtime.openOptionsPage()` で開く) を提供する。次の設定ができる:
- 娯楽サイト (ドメイン + URL) の登録/編集/削除
- 優先順位の変更 (並び替え)
- N秒判定のしきい値設定 (デフォルトと推奨範囲は FR-11 参照)

ツールバーアイコンのポップアップ内に設定UIは **持たない** (= ポップアップは存在しないか、最小限の状態表示のみ)。

### FR-10: 設定の永続化
すべての設定は `chrome.storage.local` に保存し、ブラウザ再起動後も保持されること。`chrome.storage.sync` は使用しない (端末内完結のため)。

### FR-11: N秒判定のしきい値
- **デフォルト値**: 5秒 (本要件で初期値として設定。Application Design 段階で再調整余地あり)
- **ユーザー変更**: 可 (FR-09 のオプションページから変更できる)
- **下限/上限**: Application Design で確定 (例: 1〜60秒程度の常識的範囲)

## 6. 非機能要件 (NFR)

### NFR-01: Manifest V3 準拠
Chrome の Manifest V3 仕様に完全準拠する。Service Worker ベースのバックグラウンド処理を用いる。

### NFR-02: 端末ローカル完結
すべてのデータ (設定、状態) は端末ローカルに留まる。外部サーバー、外部API、クラウドストレージへの送信を行わない。`chrome.storage.local` のみを永続化先として使用する。

### NFR-03: Chrome Web Store 申請可能な品質
- 必要最小限の Chrome 権限のみを `manifest.json` に宣言する (`tabs`, `storage`, `scripting` 等、必要な範囲)。
- ストアリスティング向けに、機能の説明 (日本語) を README または専用ドキュメントとして用意できる状態にする。
- プライバシーポリシーが要求される場合に備え、外部送信なしの旨を README に明記できる状態とする。

### NFR-04: ビルド不要
追加のトランスパイラ (TypeScript)、バンドラ (webpack/Vite) は使用しない。素の JavaScript / HTML / CSS のみで実装する。npm 依存ゼロ前提 (拡張機能の動作に必要なものだけを `src/` に直接配置)。

### NFR-05: パフォーマンス影響の最小化
- DOM 監視は MutationObserver を必要箇所に限定して張る (ページ全体を雑に観察しない)。
- N秒判定は setTimeout/setInterval を最小限に。
- 切替判定中以外はアイドル状態を維持できる設計とする。

### NFR-06: 日本語UI
オプションページのUIテキストおよびエラーメッセージは日本語のみ (今回は単一言語、i18n は将来余地)。

## 8. 用語定義

| 用語 | 意味 |
|------|------|
| AIタブ | Claude.ai (`claude.ai` ドメイン) を表示しているタブ |
| 娯楽タブ | ユーザーが登録したドメイン (動画/SNS等) のタブ |
| 待ち発生 | Claude.ai のストリーミングが N秒以上 続いている状態と判定された瞬間 |
| 完了検知 | Claude.ai のストリーミングが終わったことを DOM 変化で検知した瞬間 |
| トリガー | 「待ち発生 → 娯楽タブ自動切替」または「完了検知 → AIタブ自動切替」のいずれか |
| しきい値 (N秒) | 待ち発生を判定するためのストリーミング継続時間 (デフォルト 5秒) |
| 優先順位 | 登録された娯楽サイトの並び順。上位ほど切替先として優先される |

## 10. 制約・前提・未確定事項

### 10.1 前提
- ユーザーは Chrome デスクトップ最新版を使用している
- ユーザーは Claude.ai に既にログイン済み (本拡張は認証を扱わない)
- 娯楽タブの自動再生は、ブラウザのオートプレイポリシーやサイト側仕様に依存する。再生失敗時のフォールバックは Application Design で扱う

### 10.2 未確定事項 (Application Design / Functional Design で確定)
- N秒判定のしきい値の下限/上限と推奨デフォルト
- Claude.ai の DOM シグナル特定 (現行UIに対する MutationObserver 設計)
- 複数 Chrome ウィンドウにまたがる場合のタブ探索ポリシー (現行ウィンドウのみか、全ウィンドウか)
- 拡張機能アイコン (ツールバー) のクリック挙動 (オプション開く / 何もしない)

### 10.3 既知のリスク
- Claude.ai の UI 変更により DOM シグナルが壊れる可能性 → MVP 時点では「壊れたら直す」運用、Application Design で監視ポイントを最小限に抑えて影響範囲を限定
- 自動再生はサイト側ポリシーで失敗するケースがある → 失敗時は静かに無視 (体験フローを止めない)

## 12. 主要要件サマリ

- **WaitLess** は、Claude.ai の出力ストリーミングが N秒以上 続いた瞬間、登録された娯楽サイト (優先順位順) のタブへ自動切替し、出力完了を検知すると即座に Claude.ai タブへ戻る Chrome 拡張機能 (Manifest V3)。
- すべてのデータは端末内 (`chrome.storage.local`) に閉じる。
- 設定はオプションページに集約。ON/OFFトグル、ポップアップ設定UI、統計、他AI対応は持たない。
- MVP 品質。素の JS/HTML/CSS、ビルド不要。
